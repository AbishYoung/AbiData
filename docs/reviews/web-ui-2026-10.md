# Web UI review, October 2026

Phase R of [ADR 0015](../adr/0015-web-ui-review-and-modernisation.md). Reviewed on `web-ui-overhaul` at 88844a2 (= `public-apps` 9d31fc1 plus the ADR). Nothing in `web/src` was changed for this review; only tooling was added.

## How it was done

- **Visual inventory.** `make screenshots-review` (`node scripts/screenshots.mjs --review`, see `scripts/screenshots/review.mjs`) starts a throwaway server with the two sample workspaces and a generated password, adds an empty table and a public app, and captures 30 screens at desktop (1440×900) and 17 at compact (390×844, touch), each in light and dark: 94 images in [`web-ui-2026-10/`](web-ui-2026-10/), named `<screen>-<desktop|compact>-<light|dark>.png`. Designers, the script and job editors, imports, exports, the palette and the admin tabs other than Overview and Users are desktop only (DESIGN.md: designers show a "larger screen" note on phones).
- **Accessibility.** The same run scans every capture with axe (`@axe-core/playwright` 4.13.0, already in the e2e package; wcag2a + wcag2aa, no exclusions). Results: [`web-ui-2026-10/axe.json`](web-ui-2026-10/axe.json). The existing `tests/e2e/a11y.spec.ts` (desktop, both schemes) was run as well. Keyboard flows were walked with a scratch Playwright probe that records `document.activeElement` after each step (not committed).
- **Conformance and architecture.** A TypeScript-AST pass over `web/src` (intrinsic `title=` only, not component props named `title`; calls to `confirm`/`alert`/`prompt`; palette class names and hex literals in strings; effect counts; line counts), plus reading the large and effect-heavy components.
- **Performance.** `npm run build` output and a source-map attribution of the entry chunk by package and feature folder.

## Summary

The stack is current and the screens are, on the whole, consistent and calm; axe is clean everywhere. The real problems are **structural**: dialogs are assembled four different ways, confirmations use the browser's `window.confirm`, focus is dropped after several dialogs close, the compact Tailwind variant silently misses touch tablets, and the entry chunk carries every designer and Leaflet. The overhaul should fix those first and polish second.

## Findings

Each finding has an id, a severity, the screen(s), a screenshot where it is visual, and the proposed fix with the workstream that carries it.

### Major

**R1 · The `compact:` variant drops touch tablets.** All compact screens. `tokens.css` declares `@custom-variant compact (@media (max-width: 767px), (pointer: coarse) and (max-width: 1023px));`. Tailwind 4 splits the comma as a selector list, so the second branch compiles to an invalid selector (`.compact\:sticky (pointer: coarse) and …`, 17 "Invalid dangling combinator" warnings in every build) and is dropped. On a touch tablet between 768 and 1023 px, `useIsCompact()` and `mobile.css` say compact but every `compact:` utility is off: hover-only row actions stay invisible (`compact:opacity-100`), dialog footers do not stick, sticky first columns in query results do not stick. *Fix (O2):* the block form `@custom-variant compact { @media (…), (…) { @slot; } }`, and a test that the built CSS has no such warning.

**R2 · Focus is lost when dialogs, the palette and tabs close.** Keyboard probe on the sample workspace:
- Closing a state-controlled dialog (every dialog built on `queries/Modal.tsx`: new public app, admin users/workspaces/API keys, members, backups, query dialogs, about 17 files) puts focus on `<body>`. Radix restores focus to a `Dialog.Trigger`; these dialogs have none, and Radix's default then prevents its own fallback.
- Closing the command palette (Escape) puts focus on `<body>`.
- Closing a tab with Delete from the tab strip puts focus on `<body>`.
*Fix (O1/O2):* the `Dialog` primitive remembers the element that had focus when it opened and returns focus to it; the palette does the same; closing a tab focuses the tab that becomes active.

**R3 · Native `window.confirm` for discarding work.** Closing a tab with unsaved changes (`WorkspaceShell.tsx:92`), reloading the table design (`TableDesignTab.tsx:159`) and closing the phone record sheet with changes (`RecordSheet.tsx:166`). The browser dialog ignores the theme, blocks the event loop, reads "localhost says…", and on iOS can be suppressed. *Fix (O1/O2):* `ConfirmDialog` and an awaitable `askToConfirm()` with a host mounted next to `ErrorHost`.

**R4 · Destructive confirmations use the primary button.** `DeleteDialog` ("Delete 1 record", [datasheet](web-ui-2026-10/datasheet-desktop-light.png)), `DeleteScriptDialog`, the nav delete dialogs for tables, queries, forms, reports, scripts and jobs, and `ImpactDialog` confirm a permanent delete with `btnPrimary`, against DESIGN.md principle 2 ("`btnDanger` only inside a confirmation"). *Fix (O2):* `ConfirmDialog danger` / `Button variant="danger"`.

**R5 · Dialog chrome is implemented four ways.** 29 Radix dialog roots: `queries/Modal.tsx` (its own overlay and panel classes, used by 17 files outside queries), `dialogOverlay` + `dialogPanel` (nav CRUD, account, attachments, error), ad-hoc `bg-black/40`/`bg-black/50` overlays without `z-40`, without the `ui-overlay`/`ui-dialog` motion and with `shadow-xl`/`rounded-lg` (`DeleteDialog`, `MergeDialog`, `DeleteScriptDialog`, `ImpactDialog`, `IndexesDialog`, `JobDialogs`, `ExportDialog`, `ImportWizard`, `RowHistoryPanel`, `FormInstance`, `FormRuntime`), and the sheets. Footers are `mt-5 flex justify-end` in some and `dialogFooter` in others, so the compact sticky footer only exists in a third of them. *Fix (O1/O2):* `Dialog`, `ConfirmDialog` and `Sheet` primitives; `Modal` becomes a thin wrapper over `Dialog`; the ad-hoc overlays move onto it.

**R6 · Not-found and route-error pages are undesigned.** [not-found](web-ui-2026-10/not-found-desktop-light.png), [compact](web-ui-2026-10/not-found-compact-dark.png). A bare heading at the top left with an underlined link: no logo, no icon, no explanation, unlike every other empty state (DESIGN.md principle 7). The router's error component is the same. *Fix (O2):* a centred `EmptyState`-style page with the logo, one sentence and a primary "Back to your workspaces" button.

**R7 · The entry chunk carries every feature.** 1,632 kB (482 kB gzip). Attributed by the source map: react-dom 199 kB, **Leaflet 145 kB**, **@xyflow/react + @xyflow/system + d3 135 kB** (query designer canvas), datasheet 75 kB, **admin 71 kB**, queries 62 kB, forms runtime 58 kB, router 50 kB, **table design 47 kB**, **imports 42 kB**, nav 38 kB, **jobs 36 kB**, query-core 35 kB, reports viewer 35 kB, react-hook-form 35 kB, lucide 35 kB, **public apps 31 kB**, maps 23 kB. Only the form and report designers and Monaco are lazy. Someone opening a datasheet downloads the map library, the query canvas and the admin console. *Fix (O5):* lazy-load the query designer, table design, imports and exports, jobs, admin, the public app page and Leaflet (via the map controls), with prefetch on hover or focus of the nav item and tab.

### Minor

**R8 · Design-system drift (per-file list in the appendix).** 15 native `title=` (admin overview table cells, run history, log viewer, query results headers, report band labels, a form control, a field-type `<option>`), 29 palette classes (overlays, the auth panel's white-on-gradient, the photo viewer), 56 hex literals (Monaco theme, `SvgMap`, `WorkspaceAvatar`, the logo and the auth illustration, `viewerLogic.ts` report ink). *Fix (O2):* `Tip` for the titles that carry information (and `sr-only`/visible text where a tooltip would be the only copy); a `--scrim` token for overlays; map, avatar, report-ink and editor colours as tokens in `tokens.css` read at run time; lint guards. Documented exceptions: the photo viewer overlay and white text/marks on solid brand, kind or accent fills (logo, auth panel, avatar initials).

**R9 · Hand-assembled patterns.** Field + label + hint + error is wired by hand in 38 files (73 `aria-describedby`, 46 `aria-invalid`); skeletons in 11 files (`animate-pulse`); toolbars use `docToolbar` in 10 files and a bare `h-5 w-px` divider in 2. `EmptyState` and `SkeletonLines` already exist in `EditorParts.tsx`. *Fix (O1):* `Field`/`Input`/`Select`/`Textarea` that wire ids and descriptions; `Toolbar`/`ToolbarSeparator`; `EmptyState`/`Skeleton` move to `components/ui`. New and touched screens use them; a full migration of every field is not required for the exit criteria.

**R10 · Toolbar button styles differ by editor.** The datasheet and form toolbars use ghost buttons ([datasheet](web-ui-2026-10/datasheet-desktop-light.png), [form](web-ui-2026-10/form-runtime-desktop-light.png)); the query designer uses bordered secondary buttons for every action ([query designer](web-ui-2026-10/query-designer-desktop-light.png)); the report viewer mixes a segmented control with bordered buttons ([report](web-ui-2026-10/report-viewer-desktop-light.png)). *Fix (O3):* document toolbars use ghost buttons and one primary (Run, Save); recorded in DESIGN.md.

**R11 · Opening a form does not move focus into it.** Opening a table or query from the navigation pane focuses its grid; opening a form leaves focus on the navigation item. *Fix (O2):* focus the form's first control (or the record toolbar) as `useFocusOpenedTab` does for grids. *Deferred if it changes e2e expectations.*

**R12 · Table description is clipped.** [table-design](web-ui-2026-10/table-design-desktop-light.png): the "Table description" textarea is one line tall and cuts the text. *Fix (O3):* `Textarea` with its natural `min-h-20`.

**R13 · Admin tabs overflow on phones without an affordance.** [admin-users compact](web-ui-2026-10/admin-users-compact-dark.png): the tab list is cut at "API keys" with no fade or scroll hint. *Fix (O3):* a scrollable tab list with edge fade, or a select on compact.

**R14 · Docs panel close has a tooltip.** Focus on the close button opens its tooltip, which takes the first Escape. Dialog close buttons should not carry a `Tip` (the `Dialog` primitive puts Close last in the tab order and gives it no tooltip). *Fix (O1/O2).*

**R15 · `useMediaQuery` resubscribes on every render.** `subscribeTo(query)` returns a new function per render, so `useSyncExternalStore` removes and re-adds a `matchMedia` listener on each render of every component that calls `useIsCompact()` (shell, tab strip, datasheet, record sheet …). *Fix (O5):* cache the subscribe function per query.

**R16 · Components over 500 lines.** `DatasheetView.tsx` 1,124 (9 effects; one closure-heavy component with data paging, buffers, editing, keyboard, mouse, context menu and render), `FormInstance.tsx` 760 (8 effects), `ReportDesigner.tsx` 734, `GeoEditors.tsx` 670, `OverviewTab.tsx` 631, `FormDesigner.tsx` 629, `ReportProperties.tsx` 612, `ImportWizard.tsx` 607, `RecordSheet.tsx` 606, `WorkspaceShell.tsx` 536, `PublicAppPage.tsx` 530, `JobTab.tsx` 513. The effects reviewed are mostly legitimate synchronisation (debounced filter, layout persistence, status bar, dirty guard, scroll-into-view); the main debt is size: the datasheet's context menu, data paging and render tree are separable, and the admin overview's tables are a separate concern. *Fix (O4):* split along those seams; behaviour unchanged.

**R17 · Visual polish.** Tokens are hex with hand-noted contrast ratios and no test; there is no density setting for data views; the focus ring on inputs (`ring-3 ring-accent/20`) and on everything else (`outline 2px`) differ in weight; in dark mode the selected report band is a saturated accent block ([report designer dark](web-ui-2026-10/report-designer-desktop-dark.png)). *Fix (O3):* tokens in OKLCH with a contrast test over every documented pair in both themes, a comfortable/compact density for the datasheet and query results, one focus treatment, and a softer selected band.

### Checked and fine

- **axe:** 0 violations on all 94 captures (both themes, both widths) and in `a11y.spec.ts` (5 tests passed).
- **Keyboard:** sign-in, opening a workspace and an object from the navigation pane, cell navigation and editing (F2, Escape returns focus to the grid), the export dialog (focus returns to the "More actions" button through the menu), and the new-app dialog's first field all work by keyboard. The palette opens with focus in its input.
- **Shortcut coverage:** `lib/shortcuts.ts` documents every key handler found (datasheet, forms, designers, reports, scripts, jobs, admin charts). Mod+S is implemented per editor; there is no Mod+Enter to run a query (a possible addition, not a defect).
- **Loading, empty and error states** use `EmptyState` and `SkeletonLines` in the editors; the error dialog follows the catalog (title, message, recovery, code, request id). Bare "Loading…" text remains only inside buttons ("Load older") and a `<select>` option, where a skeleton does not fit.
- **Messages** were spot-checked on the captured screens against `docs/content` terms ("record", "field", "workspace"); no conflicts were seen. This was not an exhaustive pass over every string.

## Overhaul plan (order justified by the findings)

1. **O1 Primitives** first: R2–R5, R9 and R14 all need `Dialog`, `ConfirmDialog`, `Button`/`IconButton` and `Field`.
2. **O2 Conformance sweep:** R1, R2, R3, R4, R5, R6, R8, R11, R14, then the lint guards.
3. **O5 Performance** next: R7 and R15 are independent and measurable, and splitting chunks before O4 keeps the moved files' imports honest.
4. **O4 Structure:** R16.
5. **O3 Visual refresh:** R10, R12, R13, R17, with before/after screenshots.
6. **O6 Guard rails:** axe in e2e for the compact screens too, fail on serious and critical, document the review command.
